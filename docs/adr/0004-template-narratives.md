# ADR 0004 — Template grammar for narratives, not an LLM

**Status:** Accepted · **Date:** 2026-09-24

## Context

Every incident needs a plain-English explanation. The obvious 2026 answer is to hand the signal rows to a language model and ask for a paragraph. It would read better than anything a template produces, and it would handle cases the template author did not anticipate.

But the narrative is not decoration. It is the artifact an investigator reads to make a decision about a person, and — via the evidence pack — the artifact that reaches HR and Legal. That changes the requirements.

## Decision

Narratives are generated by a **deterministic three-layer template grammar** (headline, summary, detail bullets) that interpolates values directly from the stored signal rows. Clause fragments come from each rule's own `phrase` field.

No model is called at any point in generating an explanation.

## Alternatives considered

**LLM generation from signal rows.** Better prose, better handling of unusual combinations. Rejected on four grounds:

1. **Faithfulness cannot be guaranteed.** There is no structural bar to the model asserting something the evidence does not support. A template *is* a rendering of the evidence rows — there is no path by which it could contradict them. When the output attaches to an HR file, "we check it usually" is not an adequate answer.
2. **Determinism.** The same incident must explain itself identically today and in eighteen months when someone contests it. Sampling breaks that; temperature 0 narrows it without guaranteeing it across model versions.
3. **Offline operation.** NFR-7 requires the demo and the product to run with no internet. A security tool that phones out to explain itself is also sending incident details about employees to a third party, which is its own problem.
4. **Cost and latency per incident.** Templates are free and instant. At scale this matters; at demo time it removes a failure mode.

**Hybrid — template for the record, LLM for an optional "explain further".** Genuinely attractive, and the natural v2. Deferred rather than rejected: it needs a clear boundary in the UI between the authoritative generated record and the assistive gloss, and getting that boundary wrong is worse than not shipping it.

## Consequences

**Good.** The explanation cannot drift from the data. Output is byte-identical across runs, which makes golden-file testing of narratives possible. Zero cost, zero latency, no network, no data leaving the deployment. It is also a strong demo claim: faithfulness here is structural rather than statistical.

**Costs.** Prose is more rigid than a model would produce. Every new rule must ship a `phrase`, and CI enforces it. Unusual signal combinations produce serviceable but flat sentences. Adding a new narrative shape means adding a template.

**The position to state if challenged:** this is not LLM-avoidance on principle. It is a case where the requirements — faithfulness, determinism, offline, auditability — point clearly at a template, and choosing the boring tool because it is the right one is the engineering judgement being demonstrated.
